## G. خطة العمل المقترحة

**فورًا (قبل أي إطلاق):**
1. ربط بوابة دفع (Paymob أو Fawry أو Kashier) عن طريق `payment-webhook`، وبعد كده `paymentMode = 'gateway'`.
2. إيقاف أو مسح الحسابات التجريبية الـ ٢٠، وقفل "الحسابات التجريبية"، وشيل جدول كلمات المرور من README.
3. تفعيل Leaked Password Protection في Supabase ← Auth ← Policies.
4. ضبط SMTP (Brevo) + Site URL + Redirect URLs (`supabase/PASSWORD_RESET_SETUP.md`).

**على المدى القصير:**
- تثبيت رقم إصدار supabase-js + SRI.
- تأكيد الإيميل عند التسجيل (SEC-14).
- اختبار ضغط على مشروع منفصل بسيناريوهات A وE وF.
- تصحيح الموعد `d_t13_p1`.
- إخفاء `customer_id` من التقييمات العامة (view).

**على المدى المتوسط:**
- Pagination و lazy loading بدل تحميل كل الجداول (PERF-02).
- تقسيم `index.html` وإخراج بيانات العرض التجريبي منه (PERF-03).
- نقل الصور لـ Supabase Storage + CDN.
- CI (GitHub Actions) يشغّل `tests/` مع كل push.
- سجل تدقيق للأدمن (مين غيّر إيه) بدل سجل النشاط العام.

**على المدى الطويل:**
- خطة Supabase مدفوعة (من غير توقف، connection pooler، نسخ احتياطية يومية + PITR).
- عدّاد مقاعد على الموعد أو materialized view بدل `seat_counts()`.
- المراقبة: Sentry للواجهة و log drains لقاعدة البيانات.
- لو الحجم كبر: النقل للمعمارية المستهدفة (Next.js + Prisma) زي ما هو مكتوب في README.
